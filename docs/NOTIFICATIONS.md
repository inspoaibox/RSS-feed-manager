# 外部通知：按分类或 RSS 推送更新

每个用户在“设置 → 通知”中管理自己的频道、规则和发送记录。“通知”位于“系统设置”左侧，普通用户也可使用。

## 配置频道

飞书：在群聊中添加自定义机器人，将 Webhook 填入通知频道。支持 `open.feishu.cn` 和 `open.larksuite.com`。启用签名校验时填入对应密钥；如果使用关键词验证，建议设置关键词“RSS”。

Telegram：通过 BotFather 创建机器人并取得 Bot Token，将机器人加入目标群组或频道，授予发送权限。填写 Chat ID（例如 `-100…`）或公开频道用户名 `@channel`，群组话题可额外填写话题 ID。推送到个人聊天前，需要先向机器人发送 `/start`。部署服务器需要能访问 Telegram API。

企业微信：在企业微信群的“消息推送”中添加机器人，将 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=…` 填入频道。通知发送到该企业微信群。正文按平台的 2048 字节 UTF-8 限制截断，尽量保留原文链接；超频返回会延后重试。

邮件 SMTP：填写主机、端口、用户名、密码或授权码、发件邮箱和收件邮箱。收件人最多 20 个，以逗号、分号或换行分隔。支持 SSL/TLS（通常为 465）和 STARTTLS（通常为 587），始终校验服务器证书，不支持明文 SMTP。SMTP 登录用户名及密码/授权码仅支持 ASCII 字符，通知正文可以包含中文。QQ、163 等邮箱需先启用 SMTP 并使用授权码。旧配置中的不支持字符会记录为明确的发送失败，请重新填写授权码。不同用户可以配置不同的 SMTP 服务。

Bark：在 iPhone 安装 Bark，复制推送地址中的 Device Key。服务器默认 `https://api.day.app`，可填写自建 HTTPS 地址；仅填写服务器基础地址和密钥，不要填写已经包含 Device Key 的完整推送地址。可自定义通知分组。

PushPlus：填写个人中心的 Token，并选择微信公众号、App、邮件、第三方 Webhook、企业微信应用、浏览器/桌面插件或 QQ 机器人渠道。群组编码可选；邮件、Webhook 和企业微信应用需填写在 PushPlus 后台创建的渠道编码。先在服务侧完成实名认证和接收通道绑定。接口返回成功仅代表服务端收到请求，实际投递情况以 PushPlus 平台为准；账户受限、额度耗尽或未实名会提示手动处理，不会反复自动请求。

Server酱：填写 Turbo 的 `SCT…` SendKey，或 Server酱³ 的 `sctp…` / `sc3…` SendKey。系统自动选择对应版本和用户的发送地址。先在 Server酱绑定微信或 App 接收通道；发送额度由服务侧控制。

通用 Webhook：填写 HTTPS 接口地址，选择 POST 或 PUT。可配置 JSON 格式的请求头，例如 `{"Authorization":"Bearer your-token"}`。请求体必须是 JSON 对象，支持嵌套对象、数组和字符串模板；仅在字符串值中替换 `{{title}}`（文章标题）和 `{{message}}`（完整通知正文）。替换后仍按 JSON 序列化，文章中的引号和换行不会破坏请求体。留空时使用：

```json
{"title":"{{title}}","message":"{{message}}"}
```

通用 Webhook 以 HTTP 2xx 作为接受请求的标准，包括无正文的 204；不跟随重定向，不解析目标自定义的业务返回码。请求头不得覆盖 Host、Content-Length、连接控制或代理认证等传输头。

保存频道后点击“测试发送”。测试结果写入发送记录。编辑频道时凭据不回显，留空保留原值；飞书签名密钥可以显式清除。停用频道后，新文章不再为它生成通知，尚未发送的记录也会跳过。

SMTP 密码、各平台 Token/Key、Bark 服务器、Webhook 地址、请求头和模板均加密保存，接口不回显这些内容。编辑 Webhook 时，请求头/模板留空保留原值；勾选“清除已保存的请求头”或“恢复默认请求体”可显式重置。

## 配置规则

添加推送规则，选择自己的某个分类或 RSS，再勾选一个或多个频道。同一文章即使同时命中分类规则与 RSS 规则，也只向同一频道发送一次。内容包含文章标题、来源、发布时间和原文链接。

仅在新文章入库时匹配规则。已有文章、正文更新、重复抓取和备份恢复不会补发通知。暂停规则会停止匹配后续新文章，已经生成的待发送消息仍按原规则投递；如需立即停止这些消息，请停用频道。

## 后台发送与记录

自动推送需要现有 Celery Worker 和 Beat 都在运行。待发送记录与新文章在同一个数据库事务中保存，即使 Redis 暂时不可用，记录也不会丢失。Beat 每 15 秒派发待发送消息，Worker 每条消息独立领取，避免重复执行。

连接失败、服务端临时故障等普通故障最多自动尝试三次，并延后重试。平台限流单独处理：频道暂停至允许重试的时间，消息保留在待发送状态，不消耗普通故障的重试额度。PushPlus 账户受限、未实名等仍需人工处理。

同一频道的消息分配不同的发送时间。企业微信和 Telegram 至少间隔 3.1 秒，飞书至少间隔 0.7 秒，其他平台至少间隔 1 秒，排队时额外留出少量时间余量。数据库中的原子发送许可约束所有 Worker，延迟任务集中恢复时也不会突破频道间隔。测试发送共享频道许可，频繁点击会提示稍后再试；停用频道仍可手动测试配置。

HTTP 发送设有 20 秒的整体期限。通用 Webhook 成功时只看状态码并立即关闭响应；其他平台确认响应最多读取 64 KiB，并请求未压缩响应。超时、超大或无法确认的响应可能已经对应一次成功投递，会提示“结果未知”，不自动重发。读取响应超时或发送进程中断时，请在频道确认后手动重试，避免重复。失败的文章通知可在发送记录中重新发送，测试通知请从频道处再次测试。

全部邮件收件人以 4xx 临时错误拒收时可自动重试；永久拒收需检查地址和权限。邮件发送过程中断开、超时或部分收件人拒收时，其他收件人可能已经收到；确认收件箱后再手动重试。“已发送”表示目标接口或 SMTP 服务器接受了提交，不代表邮件已经进入收件箱或第三方平台已最终投递。发送记录中的尝试次数统计实际发送调用，限流顺延可能使其超过三次，排队等待不计入次数。

删除频道会移除规则的对应绑定，历史记录继续保留。没有频道的规则仍可备份并恢复，但不会发送消息，需要重新编辑绑定频道后才能使用；新建规则仍要求至少一个目标频道。

## 部署升级与密钥

升级后执行 `alembic upgrade head`，数据库版本应到 `041`，然后重启 API、普通 Worker 和 Beat。默认 Docker 后端会自动迁移，Worker 会等待后端健康检查。

`040` 保存各平台的加密频道配置；`041` 增加频道发送许可时间和独立的失败次数，保留现有配置、规则和历史。已经到 `040` 的实例仍需执行这次迁移，更新前后端并重启 API、Worker、Beat。升级前已经失败的通知由用户手动重试，不自动补发历史消息；本次无新增 Python 依赖。

频道凭据使用 Fernet 加密保存，接口及 HTTP 请求日志均不回显 Webhook Token 或 Bot Token。建议在创建频道前设置独立的 `NOTIFICATION_ENCRYPTION_KEY`（至少 32 字符），API 与各 Worker 必须一致；留空时使用 `SECRET_KEY` 派生加密密钥。创建频道后保持加密密钥稳定，丢失或更换密钥后需要重新保存凭据。

自定义 HTTPS 目标和 SMTP 主机沿用服务器的出站校验：默认阻止回环、内网、链路本地及保留地址，包括域名解析后的私有 IP。HTTP 连接使用安全代理固定目标 IP，SMTP 连接固定解析后的公网 IP 并按原主机名校验证书。自建 Bark/Webhook/邮件服务需提供服务器可访问的公网地址；生产环境不能开启私有目标访问。

加密备份包含通知频道和推送规则，可跨实例恢复；发送历史和待发送消息不恢复，避免旧消息误推送。备份仍需要用户自设的备份密码。

本地回归使用模拟的 HTTP 和 SMTP 服务，不使用真实机器人或邮箱凭据发送消息。部署后请用各用户自己的频道执行测试发送。
